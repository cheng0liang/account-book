# Feature Spec 001：小票识别记账 + 跨商户价格比较

**Status**: Implemented (v0.1.0) | **Constitution**: v1.1.0

## 1. 背景与目标
参考 Zaim 的移动端体验：用户用手机拍照或选图识别小票 → 自动生成可编辑表单 → 修改后保存。积累数据后，按商户、商品、时间、地区等维度比较价格并以图表展示。

非目标（本期不做）：多用户/登录、预算管理、银行账户同步、云端同步、PWA 离线写入。

## 2. 用户故事与验收标准

### US1（P1）拍照/选图识别小票并保存
- 在"扫描"页可拍照或从相册选图；客户端压缩到长边 ≤1600px 后上传。
- 服务端返回可编辑草稿：商户、时间、币种、商品明细（名称/品牌/规格/数量/单价/折扣/金额）、税额、合计、支付方式。
- 草稿中已存在的商户/商品自动匹配（填充 id）；识别合计与明细之和不一致时给出 `total_mismatch` 警告。
- 用户可增删改明细行，保存后落库；原图一并保存，可在详情查看。
- **验收**：无 OCR key 时使用 `mock` 提供商仍可走完整流程；`noop` 时得到空表单仍可手工录入；非法图片返回 400 且文案随 `Accept-Language` 本地化。

### US2（P1）商户与商品档案
- 商户：名称、国家（ISO-3166）、城市、商圈、类型、地址、经纬度。同名+同城市唯一。
- 商品：名称、品牌、分类、规格（文本/数值/单位）、条码、标签。同名+品牌+规格唯一。规格自动折算为 g / ml / 件，用于"标准单位价"。
- 保存小票时按"名称(+城市/品牌/规格)"自动查找或创建，无需先建档案。

### US3（P1）价格比较与图表
- 同一商品在不同商户的价格走势（日/周/月；avg/min/max；可按标准单位价）。
- 按商户/城市/商圈/国家/商户类型/品牌/商品维度的价格对比柱状图。
- "哪里买最便宜"列表（按最近价升序）。
- 过滤：时间区间、币种、国家/城市/商圈、商户类型、品牌、分类、标签。不同币种不混算。
- **验收**：图表接口只读预聚合表；数据未变化时重复请求返回 304；编辑/删除小票后图表立即反映。

### US4（P2）消费统计
- 首页本月汇总；按日/月/商户/类型/分类/品牌/城市/商圈分组，TopN。

### US5（P1）多语言与配置
- 简体中文 / 日本語 / English，运行时切换，持久化在 localStorage；日期与金额按语言/币种格式化。
- Nacos 可用时覆盖 `application.yml`；不可用时零报错回退并正常启动，`/actuator/health` 仍为 UP。

## 3. 非功能需求
| 项 | 要求 |
|---|---|
| 部署 | 单 jar，单 SQLite 文件（WAL），无外部数据库 |
| 前端 | 原生 ES Modules，零构建，离线可用（无 CDN） |
| 性能 | 图表查询读 `ana_price_daily`（行数 = 商品×商户×日）；ETag + Caffeine 缓存；10 万级明细下图表 p95 < 50ms（缓存未命中） |
| 可演进 | Maven 多模块 + `api/internal` 边界（ArchUnit 强制）；模块独占表前缀；事件驱动投影 |
| 安全 | 密钥仅走环境变量/Nacos；SQL 全参数化；动态排序/分组白名单；上传限制类型与大小 |

## 4. 关键决策（摘要，细节见 plan.md）
1. SQLite + `JdbcClient`，不用 ORM。
2. analytics 为 CQRS 读模型，经同步领域事件维护；可全量重建。
3. 金额存最小货币单位整数；商户本地时间存无时区 ISO。
4. OCR 通过 SPI（llm/mock/noop），`auto` 在有 key 时选 llm。
